GD&T tolerance analysis of GPS runs · C++ geometry engine in WebAssembly

Cafe on Runs

How closely do my runs pass Toronto's cafes? Let's think of each running activity captured using Garmin smartwatch GPS as one manufactured part. The intent never changes: follow the street past the cafe. Yet every run comes out a little different, because of GPS noise, the sidewalk I took, a road crossing or a detour, and tolerances decide how much of that variation is acceptable.

The City street centreline is the nominal, and each cafe is datum A. A run is accepted when it meets both callouts: ⌖ true position (its closest approach to the cafe, Ø = 2d) and ⌒ profile of a line (its worst sideways deviation from the street). A cafe conforms to both when its share of accepted runs reaches the acceptance yield, like a batch passing inspection. Every check runs in your browser, in a C++ geometry engine compiled to WebAssembly, and is redone as you move the tolerances.

About this project

What this is

A personal project. It lays every run I've recorded on my Garmin watch inside the City of Toronto over the city's cafes, and inspects the runs the way a machinist inspects parts. Each run is a part made by the same process, the City's street centreline is the nominal, and each cafe is datum A.

The half-serious question it answers: which cafes do I run past again and again, and how tightly do I hold the line when I do? The data and a C++ geometry engine compiled to WebAssembly are both inside this one file, and nothing you do here is sent anywhere.

The lot

Reading the map

  • Purple glow: my runs, each drawn separately. Brighter means more runs overlap. Runs are never averaged together.
  • Pins: one per cafe, coloured by status (see the legend under the map). Names appear when you zoom in.
  • Click a pin or a table row to inspect a cafe:
    • Dashed grey circle: the search radius R.
    • Blue dash-dot line: the street centreline. The shaded strip around it is the profile band.
    • Runs: green when accepted, red when rejected. The dots mark each run's closest point.
    • Red dashed circle: the position zone.
    • White callouts (toggle "GD&T annotations"): the datum A, a ⌖ frame for the position zone, and a ⌒ frame plus band-width dimension for each main street, each with the actual values, the way a drawing is annotated.
    • Two views: selecting a cafe shows the cafe view (blue); selecting a run shows the run view (white). The page always opens in the cafe view.
    • Click a run anywhere on the map, in either view, to open the run view (where runs overlap, a list lets you pick one). The map fits the whole run, drawn in orange with arrows for its direction; the cafes it passed are numbered in route order, every other cafe is a faint dot you can still click, and the Run report lists them with its verdict at each. A row under "Runs at this cafe" opens it too.
    • Yellow handwriting: checker's notes, written only when a cafe's runs show something worth pointing out. A yellow ① in the table marks those cafes.

The two callouts

Ø50A the run must pass through a circle 50 m across, centred on the cafe. A run's Ø is twice its closest distance to the cafe.
30 every GPS point must stay inside a 30 m strip centred on the street. It has no datum: the band follows the street, and the cafe's R circle only picks which stretch is inspected.

A run is accepted when it meets both callouts. A cafe conforms to both when its share of accepted runs reaches the acceptance yield (75% by default), from at least 3 runs.

  • Each alone, not together: each callout passes on its own, but they fail on different runs, so too few runs pass both.
  • Bias: the average sideways offset on a street. "+4.1 m N" means I tend to run on the north side. The centreline runs down the middle of the road, so a run on the sidewalk sits a few metres off it by design.

Controls

  • Search radius R: how far from a cafe a run still counts as passing it.
  • Position zone Ø and Profile band: the two tolerances.
  • Acceptance yield: the share of runs that must be accepted.
  • Year chips: filter the runs.
  • Conform to both: hides every other cafe.
  • Address bar: follows your selection, so you can copy it to share a view.

What's left out

Big chains and franchises, places tagged as cafes that aren't, cafes more than 150 m from any run (the largest R), and anything outside the City of Toronto.
